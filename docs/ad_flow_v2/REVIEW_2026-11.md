# ad_flow review — 2026-11-18 (at 5.4.0) and the v6 plan

Requested by Faiz (in Persian): review the whole package, find everything that is
wrong or improvable, and — if it is badly built — rewrite it, aiming for a package
that is policy/privacy-safe, stable, simple to use, extensible and reliable across
all his apps.

## Verdict

**Do not rewrite from scratch. Keep the engine, rebuild the surface (v6).**

The engine (seam, controllers, caps, retry, coordinator) is correct and encodes
dozens of real, verified plugin/platform traps (ADR-028 deadlock, banner callbacks
re-firing on refresh, `AdWidget` cannot re-point, inline adaptive height 0, no
plugin load timeout, clock skew, …). A rewrite would re-learn them on users'
devices. The problems are elsewhere: the package's *public surface* does not do
what the apps actually need, it recommends a flow that got two apps rejected by
Apple, and it carries a lot of machinery no app uses.

## Evidence base

- Read all of `lib/` (10,306 lines). Baseline: `flutter analyze` clean,
  `flutter test` 645/645 green (Flutter 3.47.7). `google_mobile_ads` 9.2.0 is
  still the latest release (`flutter pub outdated`, 2026-11-18).
- **Real usage**: 9 of Faiz's apps are on ad_flow 5.x — potion_sort, esmfamil,
  novels, jadval (Desktop), lebentest, Jadval (Documents/ChatGPT), nahjal_balagha,
  zanashueie_legacy, dehkhoda (AndroidStudioProjects). Every ad_flow symbol they
  use was tallied (script: grep over their `lib/` + `test/`).

## Findings (ranked)

### F1 — Client-driven ATT runs BEFORE the GDPR form → App Store rejections (critical, policy)

- `UmpConsentGateway._run` (`lib/src/consent/consent_gateway.dart:162`): step 1
  ATT primer + system prompt, step 2 consent info update, step 3 GDPR form.
  README line ~646 documents it ("your ATT primer → … Apple's system prompt, before
  GDPR"); the example defaults to this mode (`useExplainer = true`, "Recommended").
- **dehkhoda** — rejected under Guideline 5.1.1(iv), 2026-07-18/21 (build
  1.1.8(2)): "Client ATT ran *before* the GDPR form". Fixed by dropping every
  primer and letting UMP drive ATT (`home_controller.dart:219`).
- **nahjal_balagha** — rejected under 5.1.1(iv), October 2026 (2.0.1): "a reader
  who chose 'Ask App Not to Track' was then shown a GDPR form asking them to agree
  to tracking". Worked around with a 125-line `ConsentThenAttGateway` plus a native
  `MethodChannel` reading the TCF keys in `AppDelegate.swift`.
- Google's own UMP order (when the IDFA message is configured in the console):
  GDPR message → IDFA explainer → ATT, and no ATT after a GDPR denial.
- **Fix**: GDPR first, ATT after; skip ATT when GDPR applies and purpose 1 was
  not consented. The TCF keys are readable from Dart with no native code:
  `SharedPreferencesAsync` on iOS reads `UserDefaults(suiteName: nil)` by raw key
  (verified in `shared_preferences_foundation` 2.6.2 `SharedPreferencesPlugin.swift`
  `getValue`) — `IABTCF_gdprApplies` (int), `IABTCF_PurposeConsents` (string).

### F2 — `show()` resolves when the ad is DISPATCHED, not when it CLOSES

Every app that continues after an ad (next level, next round, resume reading)
re-implements the same ~40-line "listen to `state`, complete on the first state
after `AdShowing`, time out" dance: jadval `admob_interstitials.dart`, esmfamil
`admob_ads.dart` (copied from jadval), nahjal `ads_provider.dart` `_closed`.
**Fix**: `show()` completes on dismissal with a typed result (shown/closed,
not ready, blocked(reason), failed); rewarded carries the reward.

### F3 — No "can it show now?" → apps mirror the frequency caps

`isReady` means only "loaded". Caps/pacing/coordinator are checked inside
`show()`, and the cap policy is private to the facade. jadval and esmfamil each
keep `FullScreenPacing`, a hand-written copy of the cap math fed by state
listeners, "so the slot reads as not ready while the SDK would refuse it".
**Fix**: a synchronous `canShow` hint (loaded, not expired, enabled, caps,
pacing, nothing else on screen). Caps are already memory-authoritative (ADR-060),
so this is cheap.

### F4 — `showAtLaunchIfReady()` never waits → launch app-open ads almost never show

At a cold launch consent + first load have not finished, so it returns false
(novels: "the ad is rarely warm that early"). nahjal wrote its own 2.5 s budget
wait plus a wait-for-close (`startWithLaunchAd`) — under the default mode "three
app-open ads in four expired unshown". **Fix**: `showAtLaunch(maxWait:)` — waits
up to the app's own loading budget, one-shot, never shows after main content.

### F5 — Test-mode and config friction (and an invalid-traffic risk)

- `validate()` rejects a slot with no IDs even in `testMode`, where the IDs are
  replaced anyway → nahjal ships `'debug-placeholder'` IDs.
- `AdFlowConfig.test()` turns on all six formats → `initialize` then requires a
  `rewardedIntroPresenter` (potion_sort passes one only for that); esmfamil's rule:
  "`AdFlowConfig.test()` must never be used".
- `testMode` defaults to `false`: a debug run with production IDs serves live ads
  to the developer's own device — invalid traffic, an account-suspension risk.
  nahjal ties it to `kDebugMode` by hand. **Fix**: test ads automatic in debug
  builds (overridable), IDs optional in test mode, delete `AdFlowConfig.test()`.

### F6 — Large machinery that 0 of 9 apps use

| Feature | Apps | Cost |
|---|---|---|
| `forwardConsent` + `MediationConsentFailurePolicy` + consent generations | 0 | the largest share of the facade's 20 mutable fields; touches every controller |
| `RequestConfigFailurePolicy` | 0 | public enum + facade branches |
| runtime SSV (`setServerSideVerification`, `RuntimeSsvController`) | 0 | mixin + base-engine finalize hook + generations |
| client-side banner refresh (`minRefresh`, swap, `revision`) | 0 | ~150 lines of the banner controller |
| `setBlockingViewAdVisible` | 0 | coordinator state |
| `AdRequestOptions` (keywords, extras, mediation extras) | 0 | public types + mappers |
| `RetryConfig`, per-format `maxAdAge` | 0 | public knobs nobody tunes |
| rewarded interstitial, native ads | 0 in production | full formats (keep, opt-in) |

### F7 — Public API too wide → constant breaking changes

`lib/ad_flow.dart` exports 105 public types, including internals (`AdGate`,
`RetryPolicy`, `FullScreenAdCoordinator`, `StoredFrequencyCapPolicy`, the whole
seam). Every internal fix risks a major: 2.0.0 (Jul 14) → 3.0.0 (Jul 17) → 4.0.0 →
5.0.0 (Jul 20) — four majors in six days, each one to migrate in nine apps.

### F8 — Facade and docs grew by accretion

`lib/src/facade/ad_flow.dart` is 1,419 lines with 20 mutable flags across four
interlocking retry machines (consent, config, forwarding, init). The repo carries
6,800 lines of Markdown; `DECISIONS.md` is 227 KB and `PROGRESS.md` 117 KB — a
development diary, not a manual. Each audit added a guard; none removed a feature.

## What is good (keep)

- The seam (`gma_ad_sdk.dart`) and its plugin-quirk handling; `FakeAdSdk` testing.
- Synchronous claim/guard discipline (ADR-024), `tryEnter`, watchdog, catch-`Object`
  degradation (ADR-034), memory-authoritative caps + clock-skew guard (ADR-037/060).
- Banner sizing from the platform (ADR-073/078/079), `AdWidget` keying (ADR-047),
  Remove-Ads zero footprint, non-blocking init with config-after-init (ADR-028/032).

## Plan

**Phase 1 — 5.5.0, urgent, non-breaking (ship first).** ✅ Implemented
2026-11-18 (ADR-082; release pending — PR + tag).
Consent before ATT; skip ATT after a GDPR denial (TCF via `SharedPreferencesAsync`);
`skipConsentPrimerIfAttDenied` deprecated (meaningless once ATT comes last);
README/example corrected (UMP-driven ATT recommended; client ATT documented as
"after GDPR"). Tests: order, skip-on-denial, non-EEA still asked, ATT failure
never blocks ads.

**Phase 2 — v6.0.0 API (breaking, one migration).** ✅ Implemented 2026-11-18
(ADR-083/084; release pending). Item 5 was rejected (ADR-083: presenters are
already one-argument helpers); item 7 landed at 71 types, not ~30 (ADR-084:
the apps use the state, consent and controller types).
1. `show()` awaits dismissal → `AdShowResult`; rewarded returns the reward.
2. `canShow` sync hint on full-screen slots.
3. `appOpen.showAtLaunch(maxWait:)`.
4. Nullable slot getters (`ads.interstitial?.show()`), no throwing getters, no
   `…OrNull` duplicates.
5. `initialize(config, navigatorKey: key)` → built-in intro/primer screens by
   default (copy overridable); presenters stay for full customisation.
6. Test ads automatic in debug; IDs optional in test mode; delete `AdFlowConfig.test()`.
7. Exports cut to what apps use (~30 types); fakes and injectables move to
   `ad_flow_testing.dart`.

**Phase 3 — delete what nobody uses** (F6), simplifying the facade's startup into
one consent → init → config pipeline with a single retry loop. Each removal in its
own commit, tests kept green. ✅ The five subsystems went (ADR-083);
`AdRequestOptions`, `RetryConfig` and `maxAdAge` stay as small knobs; native and
rewarded interstitial stay opt-in (open decision 2).

**Phase 4 — docs reset.** README rewritten short (quick start, per-format, policy
checklist, app-ads.txt); `MIGRATION.md` 5→6; DECISIONS/PROGRESS archived under
`docs/archive/` with a short new decision log. ✅ (`DECISIONS.md` is an index +
new records; the old log and the stale v2 files are in `docs/ad_flow_v2/archive/`.)

**Phase 5 — migrate the apps** (one session per app, in its own repo). Each app
deletes its glue: `FullScreenPacing`, `PrivacyOptionsMirror`, wait-for-close
adapters, `ConsentThenAttGateway` + native TCF channel, launch-wait code. ⏳ After
the 6.0.0 release.

### Target usage (v6)

```dart
final ads = await AdFlow.initialize(
  AdFlowConfig(
    banner: BannerConfig(adUnitId: PlatformAdUnitId(android: '…', ios: '…')),
    interstitial: InterstitialConfig(adUnitId: …, cap: FrequencyCap(minGap: Duration(minutes: 2))),
    rewarded: RewardedConfig(adUnitId: …),
    appOpen: AppOpenConfig(adUnitId: …),
  ),
  navigatorKey: navigatorKey,
);

await ads.appOpen?.showAtLaunch(maxWait: const Duration(seconds: 3));
if (ads.interstitial?.canShow ?? false) await ads.interstitial!.show(); // returns after close
final reward = await ads.rewarded?.show();                           // null = no reward
AdFlowBanner(adFlow: ads, safeArea: true);
PrivacyOptionsButton(consent: ads.consent);
```
