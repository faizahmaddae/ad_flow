# DECISIONS — ad_flow v2 (ADR log)

Architecture Decision Records. Each entry: **context → decision → rationale → consequences.** Settled decisions are not to be relitigated; if you must change one, add a new superseding ADR that references it. Append a new ADR whenever you make a non-obvious choice.

Status legend: `accepted` (agreed with the maintainer / by design), `proposed` (needs confirmation as you build).

---

## ADR-001 — Ground-up rewrite to v2  ·  accepted
**Context.** v1.3.18 is feature-rich and heavily tested but architecturally constrained: all-singleton, static global config, hand-rolled observer, a lifecycle bug, and pinned to `google_mobile_ads ^7.0.0` (two majors behind).
**Decision.** Rewrite from scratch as **v2**, reusing the *battle-tested logic* of v1 (retry timing, the consent-sample flow, test-mode) but not its structure.
**Rationale.** The problems are structural, not cosmetic; a clean architecture is cheaper than incrementally untangling global state.
**Consequences.** A new `lib/` tree; v1 code stays available in git history for reference; published as a new major.

## ADR-002 — Clean v2 public API + MIGRATION.md  ·  accepted
**Context.** The package is used across the maintainer's own apps.
**Decision.** Design the best API without preserving source-compat with v1; document every breaking change in `MIGRATION.md`.
**Rationale.** A clean break with a good guide beats contorting the design for backward-compat.
**Consequences.** Consumer apps update call sites once, guided by `MIGRATION.md`.

## ADR-003 — Target `google_mobile_ads: ^9.0.0`  ·  accepted
**Context.** v9.0.0 is current (2026-06-09); core ad flow is stable 7→9; only the adaptive-banner methods were renamed.
**Decision.** Depend on `^9.0.0`; use `getLargeAnchoredAdaptiveBannerAdSize` / `…WithOrientation`. Raise package env to Flutter ≥ 3.38.1 / Dart ≥ 3.10.0.
**Consequences.** Consumer projects must meet v9's min versions (iOS 13, Android minSdk 24 / compileSdk 36, AGP 8.13.1) and adopt the iOS `UISceneDelegate` lifecycle. Documented in `MIGRATION.md`.

## ADR-004 — Dependency injection over global singletons  ·  accepted
**Decision.** No static/singleton config; `AdFlowConfig` and collaborators are constructed and injected. A convenience accessor may exist but must be backed by an injectable instance.
**Rationale.** v1's static global forced elaborate `reset()` test plumbing and made DI impossible. Injection makes every unit independently testable.
**Consequences.** Tests construct their own graph with fakes; no shared static state to reset between tests.

## ADR-005 — One reactive primitive: ChangeNotifier / ValueListenable  ·  accepted
**Decision.** Ad state is exposed as `ValueListenable<AdLoadState>`; drop v1's hand-rolled `List<VoidCallback>` observer and its duplicate broadcast stream.
**Rationale.** Idiomatic, less code, fewer bugs, integrates with `ValueListenableBuilder`.
**Consequences.** Widgets subscribe via `ValueListenableBuilder`; one notification channel per controller.

## ADR-006 — The SDK seam is the only door to google_mobile_ads  ·  accepted
**Decision.** All plugin calls go through an `AdSdk` interface (`GmaAdSdk` real, `FakeAdSdk` for tests). Nothing else imports `google_mobile_ads` except the seam and the widgets that must host an `AdWidget`.
**Rationale.** Makes everything testable without a device, and keeps the legacy↔Next-Gen native swap invisible to our code.
**Consequences.** A little boilerplate in the seam; huge testability and future-proofing payoff.

## ADR-007 — Foreground detection via AppStateEventNotifier  ·  accepted
**Context.** v1 treated iOS `inactive` AND `paused` as backgrounding, so app-open ads fired after Control Center / permission dialogs / the app-switcher.
**Decision.** Use `AppStateEventNotifier.appStateStream` (the official signal) for foreground-return; never hand-roll off `didChangeAppLifecycleState`.
**Consequences.** Correct warm-start behavior; no false app-open triggers.

## ADR-008 — Exponential backoff + jitter for retries  ·  accepted
**Decision.** `RetryPolicy` = exponential backoff with jitter, a max attempt count, a cooldown, then **auto re-arm**. Keep v1's cancellable-`Timer` approach (not `Future.delayed`).
**Rationale.** v1's linear no-jitter backoff made managers retry in lockstep and never re-armed banner/native after cooldown.
**Consequences.** Fewer thundering-herd retries; loads recover automatically after a cooldown.

## ADR-009 — FrequencyCapPolicy: per-format + global caps  ·  accepted
**Decision.** Per-format time + count caps AND a global cross-format cap, persisted through an injected key-value store.
**Rationale.** v1 had only a per-interstitial time cooldown; nothing stopped an interstitial then an app-open back-to-back.
**Consequences.** Configurable caps in `AdFlowConfig`; a user is never hit by stacked full-screen ads.

## ADR-010 — Next-Gen SDK: opt-in, Android-only, default OFF  ·  accepted
**Context.** Next-Gen is GA on native Android but experimental in Flutter (a build-time `USE_NEXT_GEN_SDK` flag); the Dart API is unchanged. iOS has no Next-Gen.
**Decision.** Build the *capability* and document it as an experimental opt-in (`--dart-define=USE_NEXT_GEN_SDK=true`); keep legacy `play-services-ads` the default; add an example build variant that turns it on. Never enable by default; don't depend on legacy-only native internals.
**Rationale.** The revenue upside (Android) is real, the effort is low (no Dart changes), and keeping it opt-in contains the risk while it's pre-GA.
**Consequences.** README documents the flag + its Android-only, experimental status; nothing in our Dart code assumes which native SDK is active.

## ADR-011 — Manual preloading (no Flutter preload API)  ·  accepted
**Context.** The Flutter plugin has no preload API even in 9.0.0.
**Decision.** "Preload" = load ahead, cache the instance, show later; every full-screen controller reloads the next in `onAdDismissedFullScreenContent` / `onAdFailedToLoad` and keeps one warm.
**Consequences.** Higher show-rate/fill without a native preload API; respect the 4h app-open expiry.

## ADR-012 — Test ads only in code; production IDs via config  ·  accepted
**Decision.** The library never hardcodes a production ad-unit ID; consumers supply per-platform IDs via `AdFlowConfig`. A `testMode` uses Google's official sample IDs. Test-mode is derived from an explicit flag/config, NOT from resolved IDs.
**Rationale.** Prevents accidental invalid-traffic strikes and fixes v1's `isUsingTestAds` false positives.

## ADR-013 — Add rewarded interstitial with mandatory intro/skip  ·  accepted
**Decision.** Implement the missing rewarded-interstitial format, including a built-in intro/announcement screen helper with a skip option.
**Rationale.** v1 had a dead test-ID constant but no implementation; the format is policy-gated on the intro screen.

## ADR-014 — Publish as 2.0.0  ·  accepted
**Decision.** Version the rewrite `2.0.0`; maintain a clear `CHANGELOG.md`; keep the same package name, repo, and pub.dev identity.
**Consequences.** Same publishing pipeline; consumers opt in via a major bump.

## ADR-015 — v1 parked under `legacy/v1/`, excluded from analysis and publish  ·  accepted
**Context.** Phase 2 scaffolds a new `lib/` in the same paths v1 occupied, but PROGRESS requires keeping v1 greppable until its battle-tested logic (retry timing, consent-sample flow, test-mode) is ported. Leaving v1 in `lib/` would collide with the new tree and break `flutter analyze` under gma 9 lints.
**Decision.** `git mv` v1 `lib/`, `test/`, `example/` → `legacy/v1/`; exclude `legacy/**` in `analysis_options.yaml`; add `legacy/` (plus `docs/`, `.claude/`) to `.pubignore`.
**Rationale.** Satisfies both constraints: v1 stays greppable in the working tree for porting, while the package analyzes clean and publishes without it. Git history additionally preserves v1 at tag/commit `c9d95d5` (v1.3.17) / `4ecef71` (v1.3.18).
**Consequences.** Delete `legacy/` once porting is complete (Phase 13/14). `flutter test` no longer runs v1's ~1000 tests — v2 rebuilds coverage phase by phase.

## ADR-016 — Seam refinements: UMP primitives live in AdSdk; view handles build their own widget  ·  accepted
**Context.** ARCHITECTURE's sketch had `ConsentGateway` "wrapping UMP", and banner/native loads "return the plugin object because a real AdWidget must host it". Invariant 8 says only the seam imports `google_mobile_ads`.
**Decision.** (a) `AdSdk` exposes raw UMP one-call wrappers (`requestConsentInfoUpdate`, `canRequestAds`, `loadAndShowConsentFormIfRequired`, `showPrivacyOptionsForm`, statuses, `resetConsent`) as clean `Future`s; `ConsentGateway` (Phase 4) becomes pure orchestration over the seam. (b) `BannerHandle`/`NativeHandle` expose `buildWidget()` — `GmaAdSdk` returns a real `AdWidget`, `FakeAdSdk` a `SizedBox` — instead of leaking the plugin ad object.
**Rationale.** (a) keeps invariant 8 literal (one gma import) and makes ConsentGateway fully testable with `FakeAdSdk`; UMP callbacks are wrapped into Futures exactly once, per the v1 trap. (b) removes the last reason for widgets to import the plugin and lets widget tests pump real trees with fakes.
**Consequences.** `GmaAdSdk` is the single gma import in `lib/` (widgets no longer need one). Fake handles are drivable test doubles shipped in `lib/src/seam/fake_ad_sdk.dart` (whether to export them for consumers' tests is part of ADR-P3).

## ADR-017 — Hand-written immutables; no freezed/build_runner (resolves ADR-P1)  ·  accepted
**Context.** ADR-P1 proposed `freezed` to cut v1's copyWith-sentinel boilerplate.
**Decision.** Hand-write the config/state immutables; add **no** build_runner dependency. Also: **no `copyWith` until a real caller needs one** — v1's boilerplate existed to serve copyWith sentinels; the v2 configs are small consts built once at startup.
**Rationale.** A library forcing build_runner on consumers is a real cost; the config surface is ~10 small classes with no unions. Prefer deleting to adding.
**Consequences.** If copyWith becomes necessary (e.g. runtime config swaps), add it narrowly to the classes that need it, or supersede this ADR.

## ADR-018 — No `appId` field in AdFlowConfig  ·  accepted
**Context.** ARCHITECTURE's sketch had `required this.appId` "(or null → set in manifest/plist)".
**Decision.** Drop the field. The AdMob application ID cannot be set at runtime by the Flutter plugin — it is read from `AndroidManifest.xml` (`com.google.android.gms.ads.APPLICATION_ID`) and `Info.plist` (`GADApplicationIdentifier`) only.
**Rationale.** A config field the SDK never reads is a lie that would burn integration time.
**Consequences.** README/MIGRATION document the manifest/plist requirement prominently. `AdFlowConfig` carries ad *unit* IDs only.

## ADR-019 — ATT handled by UMP; no `app_tracking_transparency` dependency  ·  accepted
**Context.** v1 depended on `app_tracking_transparency` and sequenced the ATT prompt itself. RESEARCH §5: UMP can present the ATT explainer and the system prompt (IDFA message configured in the AdMob console), and double-prompting must be avoided.
**Decision.** v2 has no direct ATT dependency. `UmpConsentGateway` lets UMP drive ATT; the README documents: configure the IDFA message in AdMob's Privacy & messaging, add `NSUserTrackingUsageDescription` to `Info.plist`, and do NOT also call `app_tracking_transparency` yourself.
**Rationale.** One consent surface, one prompt sequence, one less dependency; matches Google's current guidance.
**Consequences.** Apps wanting a custom pre-ATT explainer outside UMP must implement it themselves before `AdFlow.initialize`. Timeout design: only the info-update step has a timeout (30s default) — the form step never times out because the user may legitimately keep it open.

## ADR-020 — Consent flow degrades to `canRequestAds()` on failure, surfacing `lastError`  ·  accepted
**Context.** v1 swallowed consent errors with `catchError((_){})` (weakness #12); Google's sample continues after "consent gathering failed" because a previously-consented (or not-required) user should still get ads offline.
**Decision.** `ensureCanRequestAds()` never throws: update/form failures and timeouts are captured as a typed `AdFlowError` on `ConsentGateway.lastError`, and the method returns the SDK's own `canRequestAds()` answer. Concurrent calls join the in-flight run (double-load guard).
**Consequences.** Callers branch on the bool; diagnostics read `lastError`. `showPrivacyOptions()` DOES rethrow — a user-initiated surface should show its failure.

## ADR-021 — Interstitial user-action pacing activates on first `recordUserAction()`  ·  accepted
**Context.** AdMob guidance: ≤ 1 interstitial per 2 user actions. But enforcing `minActionsBetween` (default 2) unconditionally would silently block every interstitial in apps that never call `recordUserAction()` — a trap for integrators.
**Decision.** Action pacing is dormant until the app's first `recordUserAction()` call. Untracked apps are paced by frequency caps alone; once the app reports actions, `show()` requires `minActionsBetween` actions since the last show (counter resets on show).
**Rationale.** Opt-in enforcement can't brick monetization by omission, yet gives policy-conscious apps the exact guardrail.
**Consequences.** README must tell integrators to call `recordUserAction()` at natural breaks to get action pacing.

## ADR-022 — Public surface: zero google_mobile_ads re-exports; FakeAdSdk ships via `ad_flow_testing.dart` (resolves ADR-P3)  ·  accepted
**Context.** ADR-P3 proposed a minimal curated re-export of plugin types. As built, the seam's own value types (`FixedBannerSize`, `AdPaidEvent`, `RewardEarned`, `MaxContentRating`, …) cover the entire public API — no plugin type leaks through any signature.
**Decision.** The main barrel re-exports **nothing** from `google_mobile_ads`. Consumers needing plugin internals (mediation extras, custom `AdRequest`s) import the plugin directly. Test doubles (`FakeAdSdk`, fake handles) ship in a separate `package:ad_flow/ad_flow_testing.dart` barrel so consumers can unit-test their integration; `InMemoryKeyValueStore` is already public via the policy exports.
**Rationale.** Re-exporting plugin types couples consumers to plugin majors for no gain; a clean seam plus an explicit escape hatch is strictly simpler. Shipping the fakes makes downstream apps testable the same way ad_flow itself is.
**Consequences.** MIGRATION documents "import google_mobile_ads directly if you need more" (table row already present). Fake knobs become semi-public API — additive changes only.

## ADR-023 — Rewarded interstitial intro presenter is injected at `AdFlow.initialize`  ·  accepted
**Context.** The intro screen needs a `BuildContext` at show time; the facade has none.
**Decision.** `AdFlow.initialize` takes a `rewardedIntroPresenter` (e.g. `(content) => RewardedIntroScreen.show(navigatorKey.currentContext!, content)`) and **fails fast with `invalidConfig`** when the rewarded interstitial slot is configured without one.
**Rationale.** Failing at init is discoverable; failing at first show in production is not. Injection keeps the controller free of navigation concerns and testable.
**Consequences.** README shows the navigatorKey pattern. Apps with custom intro UIs pass their own presenter (must keep a skip path — policy).

## ADR-024 — Concurrency-safety pass: synchronous re-entry guards close three real races  ·  accepted
**Context.** A Phase-14 adversarial review (partially completed before hitting a spend limit — 3 of 5 finder dimensions ran, verifiers mostly failed) produced unverified findings; three were independently reproduced with hand-written repro tests and confirmed real:
1. **Double-load**: `load()` checked `_state.value` synchronously but only wrote `AdLoading` *after* `await _gate.canLoad(...)`. Two concurrent `load()` calls both passed the check, both hit the SDK, and the second call's handle silently overwrote `_handle`, leaking the first (undisposed).
2. **Double-show**: same pattern in `show()` — `_state.value = AdShowing` was written *after* `await _gate.canShow(...)`. Two concurrent `show()` calls on one controller both passed the `AdLoaded` check and both called `handle.show()` on the same single-use handle (repro: `showCalls == 2`).
3. **Cross-controller coordinator race**: `FullScreenAdCoordinator.enter()` was called only from the `AdShowedEvent` handler, i.e. after `handle.show()` resolves. Two *independent* controllers sharing one coordinator (e.g. `InterstitialAdController` + `AppOpenAdController`) each ran `AdGate.canShow`'s `if (coordinator.isFullScreenAdVisible) return false;` check — an `async` function — and since neither had entered yet, both read `false` in the same synchronous turn and both proceeded to show (repro: `bothShown == true`).
A fourth reproduced issue was a design gap, not a race: a `BannerAdController` whose one load attempt landed while the gate was closed (ads disabled / consent not yet open) dropped to `AdIdle` with no timer scheduled — nothing ever tried again, even after the gate reopened (repro: banner stayed at 1 handle forever until the fix; recovered to normal refresh cadence after).
**Decision.**
- `load()` in `FullScreenAdControllerBase`, `BannerAdController`, `NativeAdController`: write `_state.value = AdLoading` **synchronously**, before the `await _gate.canLoad(...)` call, rolling back to `AdIdle` if the gate rejects. A concurrent `load()` call now sees `AdLoading` immediately and bails — no yield point exists between the check and the write.
- `FullScreenAdCoordinator` gained `tryEnter()`: an atomic, synchronous check-and-claim (`if (isFullScreenAdVisible) return false; enter(); return true;`). `FullScreenAdControllerBase.show()` now calls `_coordinator.tryEnter()` as its first action (before any `await`), sets `AdShowing` in the same synchronous turn, and — critically — **bypasses `AdGate.canShow`'s own (still-racy) coordinator check**, calling `_gate.canLoad(slot)` + `_caps.canShow(slot)` directly instead for the remaining consent/cap checks, rolling both the coordinator claim and the state back to `AdLoaded` if either rejects. `AdGate.canShow` itself is unchanged and remains valid for external/read-only "would a show succeed" queries — it is simply no longer in the *decision* path of `show()`.
- `BannerAdController`/`NativeAdController`/`FullScreenAdControllerBase` gained `_scheduleGateRecheck()`: when `canLoad` rejects a load, reuse the existing single `_timer` field to retry after `_retry.cooldown`, exactly like the existing retry-after-failure re-arm (ADR-008) but triggered by a gate rejection instead of an SDK error.
**Rationale.** In Dart's single-threaded event loop, a synchronous check-then-write is atomic with respect to any other `async` call, because nothing else can run until the current synchronous stack unwinds to an `await`. Every one of these three races existed because the guard state was written *after* an `await`, leaving a window. The coordinator fix in particular could not be solved by moving `enter()` earlier inside `show()` alone (tried first, still raced) — it required a **synchronous** primitive on the coordinator itself, since the race was between two different controller instances, not two calls on one controller.
**Consequences.** `AdGate.canShow`'s documented contract (checks coordinator + canLoad + caps) is now accurate only for callers other than the full-screen controllers themselves; note this if adding a new full-screen-adjacent caller. All three races and the banner-recovery gap have permanent regression tests (`full_screen_ad_coordinator_test.dart` `tryEnter` group, `interstitial_ad_controller_test.dart` `concurrency safety` group, `cross_controller_coordinator_test.dart`, `banner_ad_controller_test.dart` `gate-blocked recovery` group).

## ADR-025 — Sequential invariant self-review (1,2,5,6,8,9) closes Phase 14, finds and fixes a real staleness bug  ·  accepted
**Context.** ADR-024 fixed the 3 races the spend-limited review had reproduced, but that review only completed 3 of 5 planned dimensions and never adversarially verified invariants 1, 2, 5, 6, 8, 9. Per the maintainer: "mostly verified is not good enough" for a monetization SDK. Did a focused, sequential (no parallel subagents — that's what hit the spend limit), manual pass: state each invariant, cite the enforcing code, check every path (including the ADR-024 class of "check → await → act" race, seam bypasses, static state, hardcoded ids), write a failing repro first for any hole, fix, confirm green; add or confirm a regression test either way.
**Findings, invariant by invariant:**
- **Invariant 1 (consent gates every load).** Solid: every `_sdk.load*` call in every controller is preceded by `await _gate.canLoad(slot)`, and after ADR-024 the write race is closed too. Gap found: `RewardedAdController`, `RewardedInterstitialAdController`, `AppOpenAdController` had no per-format "no load while consent closed" test (only the shared base's interstitial test covered the mechanism) — added one to each of their test files.
- **Invariant 2 (privacy options entry point) — REAL BUG FOUND AND FIXED.** `PrivacyOptionsButton` read `ConsentGateway.isPrivacyOptionsRequired` as a plain `bool` getter inside a `StatelessWidget.build()`. A widget built before the first `ensureCanRequestAds()` resolves (or mounted across a later re-check) never rebuilds when the requirement later flips true — it stays permanently hidden, violating "a persistent control MUST be available." Wrote a failing test first (confirmed the staleness both directions), then fixed: `ConsentGateway` gained `ValueListenable<bool> get privacyOptionsRequired` (backed by a `ValueNotifier`, updated everywhere `_refreshPrivacyRequirement()` runs) and a `dispose()` method; `PrivacyOptionsButton` now wraps its body in `ValueListenableBuilder`. `AdFlow` tracks whether it created its own `ConsentGateway` (`_ownsConsent`) and only disposes a self-created one, never an injected one.
- **Invariant 5 (rewarded interstitial intro+skip first).** Solid, and structurally enforced, not just by convention: `_handle` is declared in `full_screen_ad_controller_base.dart` and Dart's underscore privacy is per-FILE, so `RewardedInterstitialAdController` (a different file) cannot reach it directly — the only way to reach `handle.show()` is `super.show()`, which the subclass's override always gates behind the intro. Added a missing dispose-mid-intro regression test (confirmed already safe, no fix needed).
- **Invariant 6 (no hardcoded production ad-unit IDs).** Solid: grepped `lib/` and `example/` for `ca-app-pub` — every hit is either a doc-comment placeholder or Google's sample publisher id (`3940256099942544`). The testMode-with-a-platform-gap scenario (slot configured for Android only, testMode on, iOS still resolves to the Google sample id rather than null) was already covered by an existing test.
- **Invariant 8 (SDK seam is the only door to the plugin).** Solid: exactly one file (`lib/src/seam/gma_ad_sdk.dart`) imports `google_mobile_ads`. Turned this into a permanent executable check: `test/architecture/seam_boundary_test.dart` greps `lib/` for plugin imports outside the seam and fails if any exist (verified it actually catches a violation before relying on it).
- **Invariant 9 (no global mutable state).** Solid: the only mutable `static` in `lib/` is the sanctioned `AdFlow._instance` (ADR-004's injectable-backed convenience pointer), correctly set only after a fully-constructed instance and cleared via `identical()` on dispose. Added `test/architecture/no_global_state_test.dart`, a permanent grep-based check allow-listing only that one line (verified it catches a violation too).
**Closed the two incomplete review dimensions:**
- **seam-api**: re-verified `GmaAdSdk`'s mappings not yet spot-checked against the pub-cache 9.0.0 source — confirmed `AppOpenAd` genuinely has no `setServerSideOptions` (unlike `RewardedAd`/`RewardedInterstitialAd`), confirmed `NativeAd.customOptions` type, `AdWidget`/`FullScreenContentCallback` generics, and the rewarded `show()` `required` callback is always satisfied even when the seam's own `onUserEarnedReward` is null. No new bugs found.
- **test-gaps**: closed two gaps directly created by ADR-024/this ADR's own fixes — `AdFlow.dispose()` idempotency, and `_ownsConsent`-based disposal (self-created gateway's `ValueNotifier` becomes provably unusable post-dispose; an injected one provably survives) — plus a banner-in-unbounded-width confirming test (behavior was already correct: no load attempted, no crash, just a permanent placeholder, since an adaptive banner cannot be sized without a real width).
**Rationale.** A monetization SDK's compliance invariants are exactly the kind of thing that "looks solid" but silently breaks (invariant 2's bug required a specific mount-timing pattern — a persistent settings tab mounted at app start — that none of the existing tests happened to exercise). Sequential, single-threaded self-review with the ADR-024 race-pattern specifically in mind is what caught it; a broader adversarial fleet is valuable but not a substitute for someone actually reading the invariant text against the code.
**Consequences.** `ConsentGateway` is now a slightly larger interface (`privacyOptionsRequired` + `dispose()`); the only implementation is `UmpConsentGateway`, updated. Two new architecture tests (`test/architecture/`) act as regression guards for invariants 8 and 9 specifically, independent of any future code review. 205 tests green (up from 186 at end of Phase 13).

## ADR-026 — Independent code review (Opus, commit `3ede24d`): 1 blocker + 3 majors + 4 minors + 2 test-hardening items + nits, all fixed  ·  accepted
**Context.** A second independent review (static reading, four passes, every finding hand-verified against source — `docs/ad_flow_v2/REVIEW_FINDINGS.md`) found four must-fix defects that cluster exactly where ADR-025 predicted unit tests can't see: the live plugin seam and controller timing. Fixed in commit order, each with a failing-test-first repro; items 11-13 are lower-severity test-hardening/nit fixes from the same review, handled last per the review's own ordering.
1. **BLOCKER — a rejected `handle.show()` wedged every full-screen format for the rest of the session.** `FullScreenAdControllerBase.show()` claimed the coordinator and set `AdShowing` synchronously, then `await handle.show(...)` with no `try`/`catch`. The documented `AdSdk.show` contract says failures arrive via `AdFailedToShowEvent`, never a rejected Future — but a real implementation can violate that (ad released between load and show, channel error, mediation failure), and when it did, the exception unwound past `_exitCoordinator()`/`_dropHandle()`, leaving the coordinator claimed forever (every format shares one `FullScreenAdCoordinator`). Fix: wrap the dispatch; on catch, exit the coordinator, drop the handle, route through `AdFailed` + immediate reload — the same recovery path already used for `AdFailedToShowEvent`. `FakeFullScreenAdHandle` gained `showRejectsWith` to reproduce this without touching the real plugin.
2. **MAJOR — banner auto-refresh crashed every ~60s.** `BannerAdListener.onAdLoaded` fires on every AdMob-driven refresh of a `BannerAd`, not just the first load, but `GmaAdSdk._finishBannerLoad` called `completer.complete(handle)` unconditionally — the second firing threw `Bad state: Future already completed` as an unhandled async error. This bug lives entirely inside `GmaAdSdk`'s plugin wiring, which `FakeAdSdk` cannot model (it's one-shot, not a persistent listener) — reproducing it required real platform-channel testing, which started the seam test suite (below). Fix: guard the completion with `if (!completer.isCompleted)`, still refreshing the handle's size/collapsible fields on every firing.
3. **MAJOR — a stale retry timer stomped a since-recovered `AdLoaded`/`AdShowing` state, leaking a handle and a subscription.** `_scheduleRetry`'s timer callbacks unconditionally reset to `AdIdle` and reloaded, with no check that the controller was still `AdFailed`. If a load failed (arming a timer) and the controller separately recovered before that timer fired — a `show()`-triggered `load()` succeeding, or a direct `load()`/`reload()` call — the stale timer still fired, stomping the recovered state and starting an unrelated second load that overwrote `_handle`/`_contentSub` with no dispose of the original. Fixed in `FullScreenAdControllerBase` and `NativeAdController` (both cited) by guarding every retry callback with `if (_disposed || _state.value is! AdFailed) return;`. Also checked `BannerAdController`'s identical `_scheduleRetry` shape (not cited by name, same code) and applied the same guard for consistency — though banner's own successful-load path *always* calls `_scheduleRefresh()`, which cancels+replaces the one shared `_timer` field outright, so this specific race isn't actually reachable there; the guard is defensive, not a reproduced fix, and the banner test documents that distinction rather than claiming a false repro.
4. **MAJOR — `NativeAdController.reload()` reopened the ADR-024 double-load race.** `reload()` reset state to `AdIdle` unconditionally, even while a `load()` was already in flight (state `AdLoading`, suspended mid-SDK-call) — defeating `load()`'s own synchronous re-entry guard and letting two concurrent `loadNative` calls race, the second silently overwriting `_handle` with no dispose. Fix: `reload()` is now a no-op while `AdLoading` — the in-flight load already owns the slot and will resolve on its own. Also hardened `FullScreenAdControllerBase.discardCurrentAd()` with the identical guard per the review's precaution; its one current caller (`AppOpenAdController.show()`) only invokes it after confirming `isReady` (implies `AdLoaded`), so this isn't reachable through today's call graph, but it's `@protected` and a future subclass could call it differently.
5. **The real `GmaAdSdk` seam (~660 LOC) had zero tests** — every prior "N tests prove correctness" claim rested on "`FakeAdSdk` faithfully models the plugin," unverified. Established `test/seam/gma_ad_sdk_test.dart`, driving the actual plugin via `TestWidgetsFlutterBinding` + a mock method-channel handler for `instanceManager.channel` (pattern mirrors the plugin's own `test/ad_containers_test.dart`/`test/banner_ad_test.dart`, reachable in the pub cache under `~/.pub-cache/hosted/pub.dev/google_mobile_ads-9.0.0/test/` but not importable across packages — the ~15-line `sendAdEvent`/mock-handler setup is reproduced locally). Covers: banner load + the finding-#2 refresh crash; interstitial load-success, exactly-one-dismiss-event, `onAdFailedToLoad` → `AdFlowError` mapping through the real `AdMessageCodec`, and a rejected `show()` (confirms finding #1's premise was a real plugin failure mode, not hypothetical); `appForegroundEvents`' first subscription triggering `startListening` on the separate app-state channel.
6. **`FakeAdSdk` was more forgiving than the real SDK.** A second `show()` never failed and impossible event orderings (dismiss before show, reward after dismiss) were silently accepted — a controller bug reaching either state wouldn't have been caught. Hardened `FakeFullScreenAdHandle`: a second `show()` now emits `AdFailedToShowEvent` (matching the real single-use SDK) instead of repeating; `simulateDismissed()` before any `show()` throws `StateError`; `simulateReward()` after `simulateDismissed()` throws. Ran the full suite after each change — no existing test relied on the old over-permissive behavior.
7. **MINOR (child-directed/test-device apps: effectively MAJOR) — `updateRequestConfiguration` was gated on the consent result at init.** It sends no ad request (pure config), so gating it was unnecessary and harmful: if consent resolved *later* than init (a delayed privacy-options grant, a first-launch form that failed), controllers loading ads from that point on never got `testDeviceIds`/`tagForChildDirectedTreatment`/`maxAdContentRating`/`tagForUnderAgeOfConsent` applied — a registered test device would get live ads (self-click/invalid-traffic risk); a child-directed app would serve untagged/wrongly-rated ads (COPPA/policy risk). Fix: `_start` now runs `sdk.updateRequestConfiguration(...)` unconditionally, in the same `Future.wait` as init/consent, independent of the gate result. ARCHITECTURE.md's init sequence corrected to match.
8. **MINOR (design) — `AdGate.canShow` re-embodied the exact ADR-024 coordinator race and had no caller** — kept (public API), not deleted; its doc now warns explicitly and points to `FullScreenAdCoordinator.tryEnter()`; a test proves the race concretely (two sequential `canShow()` calls both return `true` in the same turn).
9. **MINOR (design) — an app-open ad could fire immediately behind another format's dismiss.** On dismiss, the coordinator clears synchronously, before the app's own warm-start signal necessarily settles — so only an app-configurable (and possibly zero) `globalFrequencyCap.minGap` stood between an interstitial closing and an app-open opening, unlike invariant 4's explicit "never immediately after another ad closes." Fix: `FullScreenAdCoordinator` gained a `lastExitAt` timestamp (harmless — recorded on every `exit()`, doesn't affect `tryEnter()`/`isFullScreenAdVisible`/`visible` at all, so no other controller's tests changed); `AppOpenAdManager` gained an optional `coordinator` + `postDismissSuppression` (default 1s) and skips showing — but still warms the next ad — while within that window since the coordinator's last exit, regardless of which format caused it. `AdFlow` now wires its shared `_coordinator` into the manager. One pre-existing test asserted the OLD (buggy) immediate-show behavior as correct; updated it to advance past the suppression window, and added a dedicated test for the suppression itself plus a contrast test showing no suppression applies when no coordinator is wired (documenting why the facade always passes one).
10. **MINOR — adaptive banners reserved a flat 50dp placeholder, causing residual layout shift on wider layouts.** Researched Google's actual documented bounds (web search, since RESEARCH.md didn't cover this and the formula isn't in the plugin's Dart source — it varies by device on the native side): anchored adaptive banner height is 50–90dp, capped at 15% of device height, with **no pure-width formula** — so no more-precise client-side calculation is possible without a platform round trip. `BannerAdController.reservedHeight` keeps the 50dp floor (now documented as a floor, not an estimate) and gained a `kind` getter; `AdFlowBanner` computes its own device-aware placeholder for adaptive kinds — `(MediaQuery.sizeOf(context).height * 0.15).clamp(50, 90)` — deliberately biased toward the upper end of Google's documented range, since an under-reservation (real ad taller than reserved space, pushing content down) is the direction "Layout Encourages Accidental Clicks" enforcement targets; an over-reservation only wastes some whitespace. `placeholderHeight` remains the fully-precise override when the real height is known in advance; both the dartdoc and README now say so explicitly. One pre-existing test asserted the old flat-50 placeholder; updated it, and added a dedicated test verifying the floor/mid-range/ceiling of the formula against three viewport heights.
11. **TEST HARDENING — `no_global_state_test`'s regex under-enforced invariant 9.** The `static final <UpperCamelCase-type>` exemption (added so `TestAdUnitIds`' fields wouldn't false-positive) was too broad — it would just as happily wave through `static final ValueNotifier<int> _shared = ValueNotifier(0);`, the shape invariant 9 actually guards against. Tightened to exempt only `static const`, the one construct Dart itself guarantees is immutable; no legitimate `static final` exists in `lib/` today, so this costs nothing.
12. **TEST HARDENING — invariant 6 (no hardcoded production ad-unit IDs) had no dedicated architecture-fitness test.** `ad_flow_config_test.dart` proved test-mode *behavior* is correct but nothing scanned `lib/` for a stray literal ID elsewhere in the tree. Added `test/architecture/no_hardcoded_ad_ids_test.dart`, mirroring `seam_boundary_test.dart`'s grep-the-source-tree pattern: every `ca-app-pub-<publisher>` match in `lib/` must carry Google's sample publisher id (`3940256099942544`).
13. **NIT — banner/native seam handles leaked their `StreamController`s on load failure.** `GmaAdSdk.loadBanner`/`loadNative`'s `onAdFailedToLoad` callbacks disposed the underlying `BannerAd`/`NativeAd` but never closed the handle's `_events`/`_paid` controllers — harmless in practice (the handle is discarded with nothing left listening) but inconsistent with the success path's disposal discipline. Added `unawaited(handle._events.close())`/`unawaited(handle._paid.close())` to both. No dedicated regression test: `_Gma*Handle` fields are private to `gma_ad_sdk.dart` (Dart's per-file, not per-class, privacy), so nothing outside that file can observe controller-closed state — a test would need to duplicate the seam's internals to check it, which isn't worth doing for a leak with no observable effect.
**Rationale.** Same as ADR-025: these bugs cluster exactly where unit tests structurally can't reach (live plugin wiring, timer/async races) — a second independent review looking specifically at those seams found four more real defects the first pass's invariant-by-invariant read didn't surface, because none of them are invariant violations per se; they're implementation races and a missing test layer.
**Consequences.** `test/seam/gma_ad_sdk_test.dart` is now the canonical place to add coverage for any new `GmaAdSdk` behavior — extend it rather than trusting `FakeAdSdk` alone for anything touching the plugin's actual callback/completer wiring. `FakeFullScreenAdHandle`'s stricter behavior is a (minor) breaking change for any external test code built on `ad_flow_testing.dart` that happened to call `show()` twice or drive events out of order — acceptable since `ad_flow_testing.dart` is new and pre-1.0-of-the-testing-surface.
